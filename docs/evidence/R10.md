## 3. Findings, Bugs Identified, and Remediations

### Finding 1: Mobile Horizontal Overflows & Fixed Padding (360px Viewports)
- **Before:**
  - `html` and `body` lacked `overflow-x: hidden`, allowing minor sub-pixel rendering deviations or flex child widths to trigger horizontal document scrolling.
  - Form cards in `NewEstimatePage.tsx` and `DashboardPage.tsx` utilized fixed `padding: 32px` (64px total horizontal padding), consuming ~20% of a 360px mobile screen.
  - Flex items containing project titles lacked `min-width: 0`, preventing flexbox from shrinking below text intrinsic width and causing blowout on long project names.
- **After:**
  - Added `overflow-x: hidden` and `max-width: 100vw` to both `html` and `body` in `frontend/src/index.css`.
  - Replaced rigid paddings with fluid CSS clamp: `padding: clamp(1rem, 3.5vw, 2rem)`.
  - Added `minWidth: 0`, `overflowWrap: 'anywhere'`, and `wordBreak: 'break-word'` to project links in `DashboardPage.tsx` and `EstimatesPage.tsx`.

### Finding 2: Mobile Workspace Bottom Navigation Clipping
- **Before:**
  - In mobile layout (`max-width: 767px`), the workspace navigation bar renders as a fixed bottom grid of 5 items. On 360px screens (68px width per column), multi-word items ("Budget Planner", "New Estimate", "My Estimates") clipped or wrapped unpredictably.
- **After:**
  - Updated `.workspace-nav-link` mobile styles in `index.css`: `font-size: 10px`, `line-height: 1.15`, `padding: 6px 1px`, `min-width: 0`, and clean multi-line wrapping with `overflow: hidden; text-overflow: ellipsis;`.

### Finding 3: Dark Mode Contrast Discrepancies in Header
- **Before:**
  - `Navbar.tsx` contained hardcoded `background: 'white'` and `color: 'black'` on the user account menu button, creating a jarring white circle against the dark obsidian theme (`#090D16`).
  - The dropdown container had hardcoded `border: '1px solid #e5e7eb'` (light gray), clashing with dark mode.
- **After:**
  - Replaced hardcoded styles with CSS tokens: `background: 'var(--bg-elevated)'`, `color: 'var(--text-primary)'`, `border: '1px solid var(--border-color)'`, and `boxShadow: 'var(--shadow-card-elevated)'`.
  - Subtitle "Smart Project Estimation" hidden on `< 640px` (`hidden sm:block`) to keep header buttons comfortably spaced on small mobile viewports.

### Finding 4: Action Button Toolbars on Mobile
- **Before:**
  - Buttons styled with `.btn-primary` and `.btn-secondary` had `padding: 0.625rem 1.5rem` (48px horizontal padding per button). On 360px screens, action rows in `ResultsPage.tsx` and `NewEstimatePage.tsx` overflowed or required excessive line wrapping.
- **After:**
  - Added `@media (max-width: 640px)` in `index.css` reducing button padding to `0.5rem 0.875rem` and font-size to `0.8125rem`.
  - Added `flexWrap: 'wrap'` and `gap: 12` to button rows in `NewEstimatePage.tsx`.

### Finding 5: Likely Band (P25–P75) Integration in EstimationResultView
- **Before:**
  - `ResultsPage.tsx` displayed the dual-interval (50% Likely Band + 80% Plausible Range), but `EstimationResultView.tsx` (rendered in Step 3 of the Wizard and shared views) only received `p10`, `p50`, and `p90`, omitting `p25` and `p75`.
- **After:**
  - Updated `EstimationResultView.tsx` to read `p25Hours = outputs.effort_p25_hours ?? outputs.effort_hours?.p25` and `p75Hours = outputs.effort_p75_hours ?? outputs.effort_hours?.p75` and passed them to `ConfidenceRangeBar`.
  - Added `flex-wrap gap-2` to the Uncertainty Spread Summary banner in `ConfidenceInterval.tsx`.

### Finding 6: Empirical-Bayes & Consented Actuals Section in Settings
- **Before:**
  - `SettingsPage.tsx` only exposed Full Name and Hourly Rate, lacking visibility into the Empirical-Bayes shrinkage calibration mechanism established in Checkpoint R05.
- **After:**
  - Added a dedicated **Empirical-Bayes Calibration & Project Actuals** card in `SettingsPage.tsx`:
    - Explains conjugate normal shrinkage: $w_k = k / (k + 2.83)$.
    - Displays active parameters: between-organization prior variance $\tau^2 \approx 0.187$, within-organization project variance $\sigma^2 \approx 0.529$, variance ratio $\sigma^2 / \tau^2 = 2.83$.
    - Details the $+19.52\%$ relative error reduction verified at $k=10$ actuals.
    - Notes explicit consent requirements for training data collection.
    - Exposes administrative export actions (`/api/v1/admin/actuals/export?format=csv` and `json`) when user has the admin role.
  - Added `outputs.org_calibration` status pill to `ResultsPage.tsx` and `EstimationResultView.tsx`.

### Finding 7: Touch-Friendly Responsive Tables
- **Before:**
  - The Phase Breakdown table in `ResultsPage.tsx` lacked a touch-optimized scroll wrapper.
- **After:**
  - Added `.table-scroll-container` with `-webkit-overflow-scrolling: touch; overflow-x: auto; width: 100%;` in `index.css` and wrapped tables.

### Finding 8: Eliminating Legacy Marketing Copy & Trust UX Alignment
- **Before:**
  - `SEOHead.tsx` fallback description stated `"AI-Powered Software Project Cost & Timeline Estimation"`.
  - `LandingPage.tsx` contained outdated copy: `"Automatic ML predictions are under validation and are not currently available."`
- **After:**
  - Updated all copy across `LandingPage.tsx`, `DashboardPage.tsx`, `NewEstimatePage.tsx`, `SettingsPage.tsx`, `SEOHead.tsx`, and `ModelTransparencyModal.tsx` to:
    **"PredictIQ v2.0 Monotone Power-Law with Mondrian Split-Conformal Prediction & Empirical Bayes Shrinkage"**.
