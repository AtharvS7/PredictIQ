## 1. Overview & Objectives

Checkpoint CP06 establishes the **Actuals Flywheel** for PredictIQ v2. The flywheel allows engineering organizations to close the loop on software estimations by submitting post-delivery actuals (actual person-hours, project cost, duration, and functional size delivered).

A critical architectural invariant enforced by CP06 is **explicit training consent**:
- User data must **never** be used for model retraining without explicit consent (`consent_for_training = True`).
- All admin training exports strictly isolate consented records and sanitize user-supplied notes to prevent poisoning or prompt-injection attacks.

### 2.3 API Endpoints
- **File:** [`backend/app/api/v1/actuals.py`](file:///E:/Codex/PredictIQ-dev3/backend/app/api/v1/actuals.py) (Registered in [`backend/main.py`](file:///E:/Codex/PredictIQ-dev3/backend/main.py) and [`backend/app/api/v1/__init__.py`](file:///E:/Codex/PredictIQ-dev3/backend/app/api/v1/__init__.py)):
  1. `POST /api/v1/estimates/{estimate_id}/actuals`:
     - Requires authenticated user with `editor` or `admin` role.
     - Validates that caller owns the estimate (or is admin).
     - Persists actuals with sanitized notes and explicit consent flag.
  2. `GET /api/v1/estimates/{estimate_id}/actuals`:
     - Retrieves actuals history for an estimate.
     - Enforces ownership/admin authorization.
  3. `GET /api/v1/admin/actuals/export`:
     - Restricted strictly to `admin` role.
     - Supports `format=json` and `format=csv`.
     - Filters with `WHERE ea.consent_for_training = TRUE`.
     - Joins `estimates` to extract functional size, tech stack, and project type without fabricating synthetic features.
