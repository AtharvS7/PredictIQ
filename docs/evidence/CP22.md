## 1. Objectives & Scope

Checkpoint CP22 elevates the PredictIQ estimation experience from a generic parameter form into a seamless, high-trust, startup-grade engineering estimation flow:
1. **Integration with CP21 Design System:**
   - Unified integration of CP21 component primitives (`Card`, `Badge`, `ConfidenceInterval`, and `Typography`) across all estimation touchpoints.
2. **Redesigned 3-Step Estimation Journey (`NewEstimatePage.tsx`):**
   - **Step 1: Input / Requirements & Functional Size Estimation:**
     - Sizing transparency: real-time feedback on Function Point sizing (`FunctionalSizeCard.tsx`) derived via standardized IFPUG 4.3.1 rules (~8 FP per feature unit + 5 FP per integration).
     - Flexible document upload (PDF, DOCX, TXT) with NLP parameter extraction or direct manual requirement entry.
     - Transparency indicators: data provenance badges ("IFPUG 4.3.1 Standard", "Zero Fabricated Factors") and explicit explanation of functional sizing mechanics.
   - **Step 2: Planning Parameters & Capacity Target:**
     - Real-time reactive updates (`PlanningCapacityCard.tsx`) dynamically calculating total available team capacity in hours and Person-Months at the standard **152 hrs/PM** rate (`team_size * duration_months * 152 hrs`).
     - Clear and unambiguous labeling that `Planned Target Duration` is a **target planning horizon**, *not* the ML model's predicted effort duration.
     - Zero fabricated complexity factors: eliminates arbitrary multiplier tables; all parameters represent verified constraints.
     - Live baseline target budget and monthly run-rate calculations reactive to currency conversions.
   - **Step 3: Result View (`EstimationResultView.tsx` & `ResultsPage.tsx`):**
     - Calibrated prediction ranges: p10 (optimistic), p50 (calibrated median), and p90 (conservative ceiling) presented in both **effort hours** and **Person-Months** at 152 hrs/PM (`hours / 152` PM).
     - Visual `ConfidenceRangeBar` with calibrated confidence span, target median marker pip, emerald p10 tick, and amber p90 tick.
     - Data Quality Tier Badge (Tier A Certified Benchmark, Tier B Validated Standard, Tier C Heuristic) with an accessible provenance card detailing validation methods and source repositories.
     - Out-of-Distribution (OOD) warning indicators when inputs exceed empirical calibration domains (e.g., team size > 30, duration > 24 months, FP > 2,000).
     - Clear export and save actions: one-click PDF export with currency symbol, raw JSON export, shareable link creation, duplicate estimate, and full breakdown view.
3. **Rigorous Test Suite & Verification:**
   - 100% clean TypeScript typecheck (`npm --prefix frontend run typecheck`).
   - 100% passing Vitest test suite across all 21 test files (115 tests), with zero regressions in historical contracts.
   - Flawless production build (`npm --prefix frontend run build`).

## 2. Components Created & Redesigned

### 2.1 Shared Estimation Utilities (`frontend/src/components/estimate/estimateUtils.ts`)
- `HOURS_PER_PERSON_MONTH = 152`: Standard software labor conversion (19 days @ 8 hrs/day).
- `hoursToPersonMonths(hours)`: Deterministic conversion yielding rounded float and formatted string (`e.g. "5.0 PM"`).
- `determineDataQualityTier(modelVersion, inputs)`: Maps model version and scope inputs to semantic tiers:
  - **Tier A (Certified Benchmark):** Production split-conformal models with verified functional sizing within empirical envelope.
  - **Tier B (Validated Standard):** Production split-conformal models cross-validated on empirical history.
  - **Tier C (Heuristic):** Fallback uncalibrated parametric heuristics.
- `checkIsOOD(inputs)`: Analyzes inputs against historical benchmark bounds (team size > 30, duration > 24 months, FP > 2,000, integration density > 10) and returns triggered explanations.
- `estimateFunctionPoints(features, integrations)`: IFPUG standard functional size derivation.

### 2.2 `FunctionalSizeCard.tsx` (`frontend/src/components/estimate/FunctionalSizeCard.tsx`)
- Step 1 scope calibration container built on CP21 `Card` (elevated variant).
- Displays real-time derived Function Point sizing readout with `MetricValue`.
- Shows transparency badges (`IFPUG 4.3.1 Standard`, `Zero Fabricated Factors`).
- Provides interactive feature and integration inputs with provenance guidance for spec document extraction versus manual specifications.

### 2.3 `PlanningCapacityCard.tsx` (`frontend/src/components/estimate/PlanningCapacityCard.tsx`)
- Step 2 reactive planning container displaying live capacity calculations:
  - Planned Capacity: total team hours and person-months at 152 hrs/PM.
  - Baseline Target Budget: converted into active currency (`USD`, `EUR`, `GBP`, `INR`, etc.).
  - Monthly Run-Rate: burn rate for full-time staff.
- High-trust labeling: explicit callout distinguishing user delivery target horizon from model-predicted effort duration.
- Large team notice: alerts users when team size exceeds 25 members regarding Brooks' Law coordination overhead.

### 2.4 `EstimationResultView.tsx` (`frontend/src/components/estimate/EstimationResultView.tsx`)
- Reusable, startup-grade result component used in Step 3 of `NewEstimatePage` and embedded in `ResultsPage`.
- Top header with `DataQualityBadge`, `UncertaintyBadge`, and `ModelVersionBadge`.
- Interactive Data Provenance modal / tooltip detailing empirical coverage and repository sources.
- Out-of-Distribution (OOD) warning banner with bulleted parameter violation items.
- Primary Calibrated Effort Card with `ConfidenceRangeBar` and 3-column quantile summary (hours and person-months).
- Four-card overview grid: Most Likely Cost, Timeline, Interval Coverage, and Risk Profile.
- Action toolbar: Export PDF, Export JSON, Share link, and Duplicate.
- Input parameters audit card displaying all persisted sizing and complexity parameters.

### 2.5 `NewEstimatePage.tsx` (`frontend/src/pages/NewEstimatePage.tsx`)
- Modernized 3-step wizard with step connectors, active states, and keyboard-accessible headings.
- Step 1: Integrates `FunctionalSizeCard` and drag-and-drop document upload with format validation.
- Step 2: Integrates `PlanningCapacityCard`, currency selector, and validated input fields (retaining exact labels and constraints).
- Step 3: Directly renders `EstimationResultView` upon estimation completion, allowing instant export, sharing, or deep-dive navigation to `ResultsPage`.

### 2.6 `ResultsPage.tsx` (`frontend/src/pages/ResultsPage.tsx`)
- Elevated dedicated results view incorporating CP21 `Card`, `Badge`, and `ConfidenceRangeBar`.
- Displays calibrated quantiles in both effort hours and person-months at 152 hrs/PM.
- Includes Data Quality Tier badge with provenance details and OOD warning banner.
- Added `Export JSON` action alongside existing PDF export, sharing, and duplication.
- Maintained 100% backward compatibility with persisted calculation input assertions.
